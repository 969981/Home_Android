# HOME Android 4.1.0 运行时资源缓存 — 可复现实验

## 已经证实
- APK 内的 35 个 OBJ/GLB 是 UI/场景几何，**不是完整的宝可梦本体模型集**。
- APK 已通过 UnityPy 扫描 1,471 容器、72,842 对象，仍没有物种/形态完整模型库。
- IL2CPP 恢复文件在私有 PokeHome_Resources 的 `Unpack/Android/4.1.0/il2cpp/script.json`：180,628 method entries，不能由此认定方法调用链已经验证。
- **没有实机/模拟器缓存输入**。不要声称已经获取线上模型或全部宝可梦图标。

## 需要寻找的缓存位置与特征
根据 Unity 6000 官方文档，`Application.persistentDataPath` 在 Android 常对应
`/storage/emulated/0/Android/data/jp.pokemon.pokemonhome/files`；
`Application.temporaryCachePath` 可能在应用私有缓存目录。具体路径**需要实机证实**。
Unity 磁盘 AssetBundle 缓存可能出现如下结构：
```text
RootCacheFolder/
  BundleName/
    Hash/
      __data
      __info
```
`__data` 才是可检查的资源数据，`__info` 是缓存元信息，不能简单当模型。Unity 官方说明并非全部网络加载都会进入上述缓存；此目录并不能保证完整覆盖。

### 在自己的 Android 测试设备上检查
```bash
adb devices
adb shell ls -la /sdcard/Android/data/jp.pokemon.pokemonhome/files/
adb pull /sdcard/Android/data/jp.pokemon.pokemonhome/files/ ./home41_cache_export/
```
普通非调试 APK 的内部 `/data/user/0/.../cache` 目录通常不能直接通过 adb 读取。**不要绕过设备访问控制**；只使用你能够合法导出的文件，或在自己的 root-capable 测试模拟器里按许可采集。不要上传整个应用私有目录、帐号数据库、账号资料或会话令牌。

## 脱敏缓存输入 → 来源索引
首先手工挑选只有 UnityFS/Unity SerializedFile、图片、音频等的资源缓存目录，将它传到本地独立路径，不包含帐号资料。执行：
```bash
python tools/runtime_cache_inventory.py --version 4.1.0 --cache-dir ./home41_cache_export --report ./runtime_report --out ./private_runtime_assets
python tools/pokemon_cache_scan.py --version 4.1.0 --assets ./private_runtime_assets --report ./runtime_report --out ./private_export
```
这些脚本仅保留带魔数的资产并验证 SHA-256，跳过令牌/帐号路径及未知二进制。物种 ID 仅当对象名或缓存名存在 `pm0025`、`pokemon0150` 之类明确模式时列为**候选**；绝不根据任意数字或 UI 纹理猜测。

导出结果仅放在私有仓库的 `Unpack/Android/4.1.0/runtime_cache/` 后才可汇总物种清单，且须结合模型观测、游戏 UI 及其他版本 ID 表逐项对账。输入若没有提供则输出 `runtime_cache_not_supplied`，完成工作流也不能改变事实。

## 尚需验收
- 能从真实缓存中解析 Unity 容器；记录 Container+PathID / 资源类型 / SHA-256。
- 建立物种 → 形态 → Texture2D/Sprite/Mesh/AnimationClip/Material 的实际证据链。
- 确认骨骼与动作曲线关联，生成可重开的完整 glTF/GLB 才算 3D 还原。
- 明确未缓存的远端资源，避免“未扫描到”误写为“游戏不存在”。

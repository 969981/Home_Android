# HOME Android 4.1.0 — 先确认在线运行，再评估非 UI 读取 ID

## 目标与边界

希望在不使用自动点击完成所有页面的情况下，更早观察 HOME 服务端下发的训练家资料，并在命中个人目标后让原版 APP 继续正常使用。**此目标尚未实现、没有得到真实 UTID。** 不进行服务端账号批量创建、删除、认证绕过、网络请求重放或限流绕过。

`8dee598028cd70441f645c8fff96b093b76778d625cdf07c60109eced50ffac1` 的实际安装包，不重打包。

## 之后真正应做的原生验证

前置条件：先解决实测的在线通信错误，使用自己的合法测试账号和 ARM64 **原生** Android 环境。Android x86_64+Native Bridge 能启动 ARM64 游戏不等于 Frida ARM64 RVA 在该环境能命中。

已知 4.1.0 静态观察点（来自既有 IL2CPP 研究，未在本轮动态验证）：

1. `ApiRequestAuthRegisterUser.CallAfterResponse` RVA `0x1D33294`，仅反映注册回调处理阶段；
2. `ResponseParamCommon.basic` 来源位置 `0x1D2BA60`，调用 `UDManager.SetBasic` RVA `0x1D763D0`；
3. `UD_Basic.utid` 为托管字符串引用偏移 `+0xF0`，不是裸 32 位整数；
4. `ID32 % 1000000` 仅是候选六位显示规则，仍需与官方 APP 的实际显示对账。

验证顺序：**正式授权的单个账号成功进入 HOME → ARM64 只读捕获 basic.utid → 与界面 ID 对账 → 去掉调试工具后退出重启仍保留同一 ID。** 未完成上述流程前，不应开展循环建号。

## 2026-11-07：公开仓库、免 Nintendo Account 与原生 ARM64 验证

本研究明确保持 **不绑定 Nintendo Account**。绑定 Nintendo 与否不影响本地研究代码是否能公开；公开仓库不是问题。真正需要隔离的是服务端授权会话、令牌、账户唯一标识和设备认证材料。公开 Actions 工件不能作为秘密存储。

- 公共仓库继续使用 `969981/Home_Android` 的 `master` 分支。
- [公开只读 Frida 观察器](../../ci/home41_utid_readonly_arm64.js) 仅输出命中目标的布尔值与时序，不在 Actions 中发布完整六位 ID、UTID、token、UUID、CID 或 Cookie。
- `basic.utid` 是服务器给客户端的原始字段；显示的六位训练家 ID 是否等于 `ID32 % 1000000` 尚待运行时对账。
- 公共 Actions **绝不**自动批量创建、删除 HOME 账号，也不自动接受协议。不绑定 Nintendo Account 不代表没有 Pokémon HOME 自身的服务器会话。
- 静态符号偏移需要通过严格版本哈希前置检查，ARM64 ELF RVA 不能因为 x86_64 Native Bridge 能启动游戏就宣称 Hook 已命中。

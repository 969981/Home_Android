# HOME Android 4.1.0 单次游客注册

## 真实进度

[Actions #42394020963](https://github.com/969981/Home_Android/actions/runs/42394020963) 已真实验证 Unity 原版日期选择：1999 / 4 / 5，三项 OnSelectItem 均执行，组件 isSelected、m_Value、控制器字段与真实截图一致。尚无服务端注册、首次 UTID 或六位 ID。

新增 assisted-single-signup 模式，只能在用户自己的交互终端和持久化 AVD 上使用；GitHub Actions 会拒绝启用。它先执行日期选择、严格验证原版 Unity 组件，然后自动点击已验收的生日页「下一步」一次；随后重新附加 Frida ARM64 只读监控。用户已授权同意服务协议，但未知协议页面的按钮仍不猜测坐标，必须由可核对的真实界面操作。

## 执行环境

Android 15 x86_64 + ARM NativeBridge、官方原版 HOME 4.1.0 APK、root ADB、官方 Frida Python 17.26.1、同版本 Android x86_64 Frida Server。保持模拟器可持久化，不删除数据、不重建账号。原版 APK SHA-256 会执行现有双重校验。

在 Windows PowerShell 的 Home_Android 根目录执行（修改 Frida Server 本地路径）：

~~~~powershell
git pull origin master
py -3 -m pip install "frida==17.26.1" pillow
adb devices
adb shell getprop ro.dalvik.vm.native.bridge

$apk = (Get-ChildItem ".\ROMS\4.1.0\*.apk" | Select-Object -First 1).FullName
$server = "C:\path\to\frida-server-17.26.1-android-x86_64"

py -3 .\ci\home41_emulator_arm64_realm.py --apk "$apk" --server "$server" --output ".\local-home41-single-signup" --settle-seconds 10 --probe-birthday-year --select-local-year-1999 --select-local-month-day --probe-native-full-date-select --assisted-single-signup --registration-timeout 1800
~~~~

只有当年/月/日真实显示和 ARM64 内部状态均通过，才自动点一次年龄页面的「下一步」，并检查页面确实切换。之后开始只读注册监听。待终端出现 arm64_auth_observer_ready，再在原版 APP 里继续：

1. 已自动检查生日 1999 / 4 / 5 并点击一次年龄页「下一步」；禁止再次点击同一页或重建账号。
2. 用户在 2026-11-08 明确授权同意 HOME 服务协议；确认当前出现的是原版 HOME 的协议界面，再点该界面的同意按钮。原版协议页的具体控件还没有截图验收，代码不会猜坐标。
3. Nintendo Account 选择官方允许的不绑定/跳过路径；避免错绑已有账户。
4. 选择首个有效头像、小火龙（全国图鉴 #0004），按实际官方页面完成一次游客初始化。
5. Frida 会观察原版注册、Token、登录与 SetBasic。初始 basic.utid 与六位候选仅在本人交互终端输出，不会写入 Actions、GitHub、JSON 或公开日志。

## 协议页独立探针（已接入 CI 离线测试）

原版 HOME 的生日「下一步」已经在 [Actions #42395325060](https://github.com/969981/Home_Android/actions/runs/42395325060) 通过真实设备模拟器测试，但**后续协议页尚未取得可校验的原版页面截图与可访问性节点**。因此新工具采用严格 fail-closed 原则：未知 Unity 绘制页面无可访问性标注时，不会猜坐标，也不视为已同意。

~~~powershell
# 在原版 HOME 的服务条款界面上，先只读检测：
py -3 .\ci\home41_terms_probe.py --stage terms_next
# 确认页面与按钮唯一、并且本次注册已授权同意条款后：
py -3 .\ci\home41_terms_probe.py --stage terms_next --tap-confirmed-consent

# 下一页仍需确认页面身份（不要复用旧的点击坐标）：
py -3 .\ci\home41_terms_probe.py --stage final_agree
py -3 .\ci\home41_terms_probe.py --stage final_agree --tap-confirmed-consent
~~~

工具只在检测到 HOME 前台、条款与隐私文字、唯一且已启用的对应按钮时允许点击；点击前会再次获取完整 UI 节点树防止页面切换误点。原始 XML 在设备上临时写入、读取后立即删除，不保存到本机或 GitHub。只有识别为协议页的截图才会本地保存（遮盖系统状态栏），不在 CI 上传账户隐私。

本次用户明确授权同意协议，但这不等于 Android HOME 已经执行同意动作。第一次 NEXT / 最终 Agree 以及账户注册、真实 basic.utid 均须独立运行证据。

## 生日后的实际协议页面：只读结构化实测

已增加 [只读探针工作流 #42459707874](https://github.com/969981/Home_Android/actions/runs/42459707874)：它通过原版 1999/4/5 年月日的本地/Frida 校验后，点击生日页原版「下一步」**一次**，接着只读取 Android UI 可访问性结构，不做任何协议同意、注册或账号关联。

可公开输出的字段只有：`age_next_native_verified`、`home_foreground`、`terms_marker`、`privacy_marker`、`unique_terms_next_button`、`unique_final_agree_button` 等布尔标记，绝不保存原始 XML、实际按钮坐标、屏幕截图、服务端回包或 ID。若 HOME Unity 页没有暴露可访问性文字，结论为「不可访问」，不能据此推断已进入或同意协议页。

这是一项**取证任务，不是账号创建任务**。真实账号、真实 UTID 的验收仍需要持久化模拟器或本人设备中运行正常的官方注册流程。

[原版 HOME 4.1.0 控制器研究文档](https://github.com/969981/PokeHome_Resources/blob/4.1.0/docs/obsidian/HOME41_ANDROID_FIRSTBOOT_TERMS_NATIVE_CONTROLLER_20261108.md) 现已定位：

- FirstBootBodyController.SetUpContentsForConfirmationTerms：RVA 0x1DE2400；

这些都已由原始 ScriptMethod 和 dump.cs 交叉确认，但仍是**静态映射**，不代表运行时协议已出现或按钮被点击。Frida 新增可选只读 Hook 记录协议 UI 函数命中，不写 Checkbox、不修改服务器数据、不自动同意条款。

最新的 [真实生日后 UI 取证 Actions #42459707874](https://github.com/969981/Home_Android/actions/runs/42459707874) 已确认生日 Next 和新页面均成功，但 UIAutomator 未暴露协议文字/按钮；因此这一步需要先等原版 Unity 原生控制器事件实测闭合。

## 验收

- 注册/登录/首次 Basic 由真实 ARM64 原生事件的时间线确认，不以 Hook 已安装替代事件实际命中。
- 首次 basic.utid 与六位候选的模 1000000 换算仅是假设；必须另与 HOME 页面显示的六位训练家 ID 及小火龙 OT ID 做独立核对。
- 原模拟器冷启动后必须能恢复同一账户。不可用 Actions 中会被销毁的临时 AVD 创建真实持久账号。
- 如果服务端错误、日期显示不正确、条款/绑定页面未知，停止，不删除、不重试批量创建。

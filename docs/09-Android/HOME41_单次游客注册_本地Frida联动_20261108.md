# HOME Android 4.1.0 单次游客注册

## 真实进度

[Actions #42394020963](https://github.com/969981/Home_Android/actions/runs/42394020963) 已真实验证 Unity 原版日期选择：1999 / 4 / 5，三项 OnSelectItem 均执行，组件 isSelected、m_Value、控制器字段与真实截图一致。尚无服务端注册、首次 UTID 或六位 ID。

新增 assisted-single-signup 模式，只能在用户自己的交互终端和持久化 AVD 上使用；GitHub Actions 会拒绝启用。它先执行日期选择，再重新附加 Frida ARM64 只读监控；后续未知页面不猜测坐标或自动同意协议。

## 执行环境

Android 15 x86_64 + ARM NativeBridge、官方原版 HOME 4.1.0 APK、root ADB、官方 Frida Python 17.26.1、同版本 Android x86_64 Frida Server。保持模拟器可持久化，不删除数据、不重建账号。原版 APK SHA-256 会执行现有双重校验。

在 Windows PowerShell 的 Home_Android 根目录执行（修改 Frida Server 本地路径）：

~~~~powershell
git pull origin master
py -3 -m pip install "frida==17.26.1" pillow
adb devices
adb shell getprop ro.dalvik.vm.native.bridge

$apk = (Get-ChildItem ".\ROMS\4.1.0\*.apk" | Select-Object -First 1).FullName
$server = "C:\path\to\frida-server-17.26.1-android-x86_64"

py -3 .\ci\home41_emulator_arm64_realm.py --apk "$apk" --server "$server" --output ".\local-home41-single-signup" --settle-seconds 10 --probe-birthday-year --select-local-year-1999 --select-local-month-day --probe-native-full-date-select --assisted-single-signup --registration-timeout 1800
~~~~

只有当年/月/日真实显示和 ARM64 内部状态均通过，才开始只读的注册监听。待终端出现 arm64_auth_observer_ready，再在原版 APP 里人工完成：

1. 检查真实 UI 生日仍为 1999 / 4 / 5，点击下一步并核对正式确认信息。
2. 本人阅读真实服务条款与隐私声明，决定是否同意；工具绝不代替用户同意条款。
3. Nintendo Account 选择官方允许的不绑定/跳过路径；避免错绑已有账户。
4. 选择首个有效头像、小火龙（全国图鉴 #0004），按实际官方页面完成一次游客初始化。
5. Frida 会观察原版注册、Token、登录与 SetBasic。初始 basic.utid 与六位候选仅在本人交互终端输出，不会写入 Actions、GitHub、JSON 或公开日志。

## 验收

- 注册/登录/首次 Basic 由真实 ARM64 原生事件的时间线确认，不以 Hook 已安装替代事件实际命中。
- 首次 basic.utid 与六位候选的模 1000000 换算仅是假设；必须另与 HOME 页面显示的六位训练家 ID 及小火龙 OT ID 做独立核对。
- 原模拟器冷启动后必须能恢复同一账户。不可用 Actions 中会被销毁的临时 AVD 创建真实持久账号。
- 如果服务端错误、日期显示不正确、条款/绑定页面未知，停止，不删除、不重试批量创建。

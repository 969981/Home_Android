# 研究目标与证据等级

在原版 HOME Android 4.1.0 的一次性 Android 15 x86_64 模拟器里，连接 Frida，仅观察语言/地区操作的时序和**匿名网络调用计数**，不用注册账号、绑定 Nintendo Account、选择生日、点击服务协议或捕获令牌。

- 原 APK SHA-256：`8dee598028cd70441f645c8fff96b093b76778d625cdf07c60109eced50ffac1`。
- 原 ARM64 `libil2cpp.so` SHA-256：`80bfbc3d480bf3c91297d65a441a37e40260b70fd8b0ddc8da70c34f0870b6fe`。
- 模拟器客体：`x86_64,arm64-v8a`，Native Bridge `libndk_translation.so`。能启动 ARM APK **不等于** ARM64 Frida RVA 可用。
- 原版真实 UI 证据：[Actions #42357608036](https://github.com/969981/Home_Android/actions/runs/42357608036)，语言选择为简体中文、语言确认并展开亚太国家列表，**未选地区、未注册**。
- 新实验：[HOME x86 Frida UI / network-stage Actions](https://github.com/969981/Home_Android/actions/workflows/home41-emulator-frida-stage.yml)（必须读取这轮运行的 Artifact 才能记录真实结果）。

## 1. 已知哪些是真接口字段？

| 阶段 | UI/本地字段（可能为本地状态） | 已知静态接口字段 | 能否称作“接口返回” |
| --- | --- | --- | --- |
| 选简体中文 | HOME UI 语言偏好 | 原生 Android 注册请求 DTO 有 `lng` | **不能**；只有请求序列化/HTTP 行为实测后才能证实何时提交 |
| 展开亚太地区 | 列表国家选项 | 原生注册请求 DTO 有 `cntry` | **不能**；列表可能内置于客户端资源 |
| 选中国大陆 | 地区 UI 选择 | 预计与 `cntry` 有关联 | **待证**；未见真实入网请求 |
| 账号注册 | 正常注册流程 | `ApiRequestAuthRegisterUser.SerializeRequestParameter` 包含 `csrf,state,nonce,lng,cntry,said` | 是原生**请求端**静态字段，不是服务端实际回包内容 |
| 登录 / basic 资料 | `ResponseParamCommon.basic` | `UDManager.SetBasic`、`UD_Basic.utid +0xF0` | 有真实原生解析路径，但 x86_64 模拟器未能验证动态 Hook、未见 UTID |

注册请求的字段集合来自已有 HOME Android 4.1.0 逆向研究；该表不允许把 UI 文本或静态字段误称为“实际服务器返回”。

## 2. 新的 Frida 观测点

- `ci/home41_emulator_network_meta.js`：仅对 x86_64 进程导出的原生 `connect()` 和 `getaddrinfo()` 做被动计数。严格不读取主机名、IP、HTTPS 请求体、路径、表单内容、响应 JSON、认证令牌；不加载 Java Bridge 或 ARM64 IL2CPP 的静态 RVA。
- `ci/home41_emulator_stage_frida.py`：只在 Actions 一次性模拟器内部部署与 Python `frida` 同版本的 x86_64 frida-server，使用本地 ADB 转发后附加原版 HOME，分阶段调用无敏感信息的 `setstage()` RPC。
- `ci/home41_emulator_diagnostics.py`：沿用在真实截图上已校验的英语/中文切换、确认、展开亚太地区的 UI 导航。如果选择“中国大陆”的特征图案无法确认，则**不触碰页面**；不会进入生日/条款/账户创建。
- `.github/workflows/home41-emulator-frida-stage.yml`：实际 Android 15 KVM AVD、原 APK 哈希核验、Frida x86_64 二进制、截图和聚合报告，输出 `home41-x86-frida-ui-stage-evidence`（保留 3 天）。

按时间分五段：

```
launch → language_selected → language_confirmed → region_expanded → country_selected
```

每段记录：`connect` 总次数、`getaddrinfo` 总次数、按 IPv4/IPv6/其他 socket 类型分类的连接次数，以及 Hook 的成功/失败状态。所有数据是**UI 操作窗口附近的网络调用数量**，不表示一条网络请求、一个 API endpoint、一条成功连接或一份实际返回资料。

## 3. x86_64 Native Bridge 限制

Frida 装在 Android 的 x86_64 原生进程里可能观察到进程的 libc socket API；然而 HOME 部分 ARM64 native library 经 Native Bridge 翻译执行，不保证网络调用会穿过已经 Hook 的 x86_64 libc。因而：

- `frida_attached_to_home_x86_64` 只证明 x86_64 Frida 会话附加成功。
- `connect_hook_status=attached` 和 `getaddrinfo=attached` 只证明 libc 函数入口安装 Hook 成功。
- 某个 UI 阶段计数增加，不足以证明 HOME 接口发送了 `lng` / `cntry` 或取得服务器响应。
- 计数为 0，也不能证明无流量：可能复用连接、Native Bridge 翻译路径、其他网络栈、附加时机等。
- 动态 ARM64 `SetBasic`、`basic.utid`、六位 ID，必须在**真正 ARM64 Android 客体**另外测试。

## 4. 安全及复现实验规则

`Frida` 是只读元数据观察：不使用 TLS 密钥/证书篡改，不记录或上传接口正文和令牌，不调用注册或删除 API。不涉及批量账号，不触发协议、出生日期或 Nintendo 账号绑定。

公开 Artifact 只能保留未登录 UI 截图、固定白名单 JSON 字段、连线次数、状态和脱敏异常**类型**。没有设备真实私有数据、网络包、cookies、UTID、UUID、CID、设备标识或完整 logcat。

下一轮若要研究**实际哪个 HTTP 响应带了 language/country/basic**，需要先证明接口确实被调用，再在获得授权的真实原生 ARM64 环境中对**已解析业务 DTO 的字段名及是否存在**做只读监控，而不是把网络计数说成接口内容。

Frida 实测：
- 使用 x86_64 Android 15 AVD，Python `frida==17.26.1` 与官方匹配的 Frida Server。
- 此环境的 `frida-server -D` 守护进程启动方式失败；Android shell 后台启动替代方案成功，实际 `frida_attached_to_home_x86_64`，agent 加载成功，`process_arch=x64`。
- `connect` 和 `getaddrinfo` 入口 Hook 均 `attached`。分五个阶段返回的 **Hook 可见** `connect` 次数、`getaddrinfo` 次数全部为 **0**，并没有缓存、导出任何网络请求内容或返回 JSON。
- 这**不是**“HOME 没有网络连接”的结论；ARM Native Bridge 的 ARM64 代码网络路径、连接复用以及在 Hook 附加之前发起的连接都可能不经过被观察的 x86_64 入口。
- 也不是“接口返回了简体中文、中国大陆”的证据。当前可靠证据是用户界面的两个选择被确认，并切换到生日页面；静态请求 DTO 包含 `lng`、`cntry`，但未动态确认请求发送时刻。

### 后续技术决策

1. 若目标只是验证 HOME 启动时语言/地区 UX 阶段，现有无账号模拟器流程已闭合到 **生日页面**。
2. 若要确认 `lng`、`cntry` **确实进入了哪个 HTTP 请求**，需要观察实际网络/序列化调用，不得把 x86_64 libc 计数当作覆盖了 ARM Native Bridge 的网络 API。
3. 若要获取服务器真正下发的 `basic.utid`、六位训练家 ID，必须在原生 ARM64 Android 环境完成单次合法初始化后对 `ResponseParamCommon.basic → UDManager.SetBasic` 进行动态观察，并核对小火龙自身 OT ID。该项在本实验仍为 **未验收**。
